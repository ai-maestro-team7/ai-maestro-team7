## ★ 함수 명세 (현지 → 백엔드)

백엔드는 **세션 데이터를 꺼내고 → 현지 함수를 부르고 → 돌려받은 값을 저장**만 합니다. 면접 규칙(꼬리질문 최대 1개, 무응답·변환 실패 처리, 리포트 시점)은 함수 안에서 처리하므로 백엔드는 규칙을 몰라도 됩니다.

### 백엔드가 부르는 함수

| 함수 | 언제 | 입력 | 출력 |
| --- | --- | --- | --- |
| `start_interview` | `/start` 202 응답 후 뒤에서 | session_id, job, resume_text, interview_type, camera_consent, profile(선택) | session(초기 세션 데이터), nextQuestion |
| `synthesize_question` | 다음 질문이 정해질 때마다 | text | mp3 bytes (백엔드가 S3 저장 후 임시 URL 발급) |
| `start_transcription` | 백엔드가 녹음을 S3에 올린 직후 | s3_uri, job_name, media_format, output_bucket, output_key | job_name (변환 결과는 `output_bucket`의 `output_key`에 저장) |
| `get_transcription_result` | 변환 완료 확인 시 (뒤에서 처리하는 작업이 완료될 때까지 반복 조회) | job_name | status(IN_PROGRESS / COMPLETED / FAILED), text, words |
| `process_answer` | 변환 결과가 나온 뒤 | session, answer_result | session(갱신), action, nextQuestion, lastAnswer |
| `analyze_face` | `/frame` 요청마다 | image_bytes | valid, reason, gaze(yaw·pitch), head(yaw·pitch), eyesOpen(value·confidence) |
| `compute_baseline` | 보정 캡처가 끝난 뒤 | 보정용 analyze_face 결과 목록 | baseline (유효 3장 미만이면 None → 태도 미측정) → 백엔드가 `session.baseline`에 저장 |
| `generate_report` | action이 `REPORT`일 때 | session, frames | report |

### 내부 함수 (현지만 사용)

| 함수 | 역할 |
| --- | --- |
| `generate_questions` | 프롬프트 A: 질문 3개 + 유형 |
| `judge_follow_up` | 프롬프트 B: 꼬리질문 필요 여부 |
| `evaluate_content` | 프롬프트 C-1: 항목별 1~5점 + 근거 |
| `write_feedback` | 프롬프트 C-2: 확정 점수로 피드백 |
| `measure_delivery` | 발화 속도, 분당 긴 침묵, 시간 관리 |
| `measure_attitude` | 정면 응시 비율 |
| `calculate_interview_scores` | session, frames, config → 영역별·종합 점수, 등급, 미측정 사유 (DB를 읽지 않음) |

### 주요 데이터 형식

```python
# session (백엔드는 받은 그대로 저장하고 다음 호출에 그대로 넘김)
{
  "sessionId": "6f1c2a9e-...",
  "job": "백엔드 개발", "interviewType": "MIXED", "cameraConsent": True,
  "resumeText": "...", "profile": None, "scoringVersion": "v1.0",
  "questions": [{"questionId": "q1", "questionType": "experience", "question": "..."}],
  "currentIndex": 0, "followUpUsed": False,
  "answers": [], "baseline": None
}

# process_answer 입력 answer_result
{
  "answerId": "a-q1-1",
  "timeLimitReached": False,
  "transcription": {"status": "COMPLETED", "text": "...", "words": [{"word": "저는", "start": 0.4, "end": 0.7}]}
  # 변환 실패: {"status": "FAILED"} / 말이 없음: text가 빈 문자열
}

# process_answer 출력
{
  "session": {...},
  "action": "FOLLOW_UP",   # FOLLOW_UP / NEXT_QUESTION / REPORT
  "nextQuestion": {"questionId": "q1-f", "answerId": "a-q1-2", "text": "...", "isFollowUp": True},
  "lastAnswer": {"answerId": "a-q1-1", "evaluable": True, "reason": None}
}

# frames (백엔드가 analyze_face 결과에 붙여 저장)
[{"type": "ANSWER", "questionId": "q1", "answerId": "a-q1-1", "capturedAt": "...", "accepted": True,
  "valid": True, "gaze": {"yaw": -1.8, "pitch": -9.9}, "head": {"yaw": 1.5, "pitch": 8.0},
  "eyesOpen": {"value": True, "confidence": 96.1}}]
```

### 백엔드와의 약속

- `sessionId`는 백엔드가 만들어 `start_interview`에 넘김 (202 응답에 바로 쓰기 위해)
- `answerId`는 함수가 질문과 함께 발급, **중복 제출 확인은 백엔드**
- 답변 제출 이후 도착한 이미지는 백엔드가 `accepted: false`로 저장 → `generate_report`가 제외
- `compute_baseline` 결과는 백엔드가 `session.baseline`에 넣어 저장 → `generate_report`가 이 값으로 정면 판단 (`None`이면 태도 미측정. 백엔드는 대체값을 넣지 않고 그대로 저장·전달)
- 눈 감음 판단은 `analyze_face`가 아니라 점수 계산 단계에서 `eyesOpen.confidence`로 함 (`analyze_face`는 눈 감음만으로 `valid: false`를 주지 않음)
- Transcribe 결과는 백엔드가 정한 `output_bucket`·`output_key`에 저장하고 함수가 S3에서 읽음 (Lambda가 VPC 안에 있어도 동작). 경로 예: `uploads/interview/{ivId}/transcripts/{answerId}.json` (`uploads/` 7일 자동 삭제 규칙 적용). 결과 파일에 답변 원문이 들어 있으므로 백엔드가 녹음을 지울 때 함께 지움
- 함수 입력 인자 이름은 Python 표기(밑줄), 돌려주는 데이터의 키는 카멜 표기
- 함수는 **DB·API를 직접 부르지 않음**. Bedrock·Polly·Transcribe·Rekognition만 호출
- 오류는 `InterviewError(code, message, retryable)`로 발생 → 백엔드가 팀 공통 오류 형식으로 변환 (`INVALID_INPUT` / `AI_OUTPUT_INVALID` / `AWS_SERVICE_ERROR`)
- 리포트는 백엔드가 저장하고, 다시 열면 저장된 값을 반환 (`generate_report`를 다시 부르지 않음)
- 설정: 모델 ID는 환경변수 `MODEL_ID`, 점수 기준은 `interview/config/scoring_v1.json`
- 위치: 같은 저장소 `interview/` 폴더, 단계별 PR로 전달
- 함수 로그에 자소서·답변 원문을 남기지 않음

## 2. 아키텍처

### 2.1 구성도

```
[브라우저 (프론트 담당)]
  녹음 · 2분 타이머 · 카메라 캡처 · /status 2초마다 조회
        │
        ▼
[API Gateway]  /api/v1/interview/*
        │
        ▼
[Lambda (Python)]
  ├─ start   : 세션 생성 → 질문 생성 작업 등록
  ├─ answer  : 녹음 S3 저장 → Transcribe 작업 시작
  ├─ status  : 상태 조회만 (처리는 하지 않음)
  ├─ frame   : 이미지 → Rekognition → 각도만 저장
  └─ task    : 뒤에서 처리 (Lambda 비동기 자기 호출) → 질문 생성, 변환 확인, 꼬리질문 판단, 리포트 생성
        │
        ├──▶ [면접관 에이전트 (Strands)] ──▶ [Bedrock 모델]
        ├──▶ [Polly]        질문 → 음성 (S3 임시 URL)
        ├──▶ [Transcribe]   답변 음성 → 텍스트 + 단어별 시간
        ├──▶ [Rekognition]  시선·고개 각도
        ├──▶ [S3]           녹음·질문 음성 임시 보관
        ├──▶ [DynamoDB]     세션·답변·측정값·리포트
        └──▶ [CloudWatch]   로그
```

- 담당: API Gateway·Lambda·S3·DynamoDB·CloudWatch = **백엔드** / 면접관 에이전트·Polly·Transcribe·Rekognition 호출·측정·점수·리포트 = **현지 함수**

### 2.2 처리 흐름 (코드 이름은 백엔드가 호출하는 현지 함수)

1. **[면접 준비]** → `POST /start` → 백엔드가 세션 ID 생성, 202 반환 → 뒤에서 `start_interview` + `synthesize_question`
2. 화면은 `/status`로 `NEXT_QUESTION_READY` 확인 → **[면접 시작]** 활성화
3. 질문 음성 재생 → 녹음(최대 2분) + 카메라 2초마다 `POST /frame`
4. **[답변 완료]** → `POST /answer` → 202 → 뒤에서 처리
    - 백엔드가 녹음을 S3에 저장 → `start_transcription` → `get_transcription_result`로 완료 확인 → `process_answer`(전달력 측정, 꼬리질문 판단, 최대 1개 규칙) → `synthesize_question` → 백엔드가 저장·상태 갱신
5. 3번째 기본 질문 처리 후 리포트 생성
    - `generate_report(session, frames)` 하나만 호출 (내부 순서: 내용 평가 C-1 → 태도 측정 → 점수 계산 → 피드백 C-2) → 백엔드 저장
6. `/status`가 `COMPLETED` + 리포트 반환

### 2.3 주요 결정

| 결정 | 이유 |
| --- | --- |
| 접수 후 상태 조회 (202 + `/status`) | Transcribe·AI 처리 시간이 API Gateway 시간 제한(약 30초)을 넘을 수 있음 |
| 뒤에서 처리하는 방식: **Lambda 비동기 자기 호출** (`InvocationType=Event`, 결정 기록 D-19) | SQS 권한이 없어 이 방식으로 정함. SQS 권한이 생겨 필요하면 전환 (현지 함수는 어느 방식이든 입출력이 같음) |
| AWS 서비스 호출·점수 계산은 에이전트 툴이 아닌 일반 코드 | 매번 반드시 같은 순서로 실행돼야 하는 처리라 AI 판단에 맡기지 않음 |
| Nova Sonic 대신 Transcribe + Bedrock + Polly | Bedrock Nova Sonic은 한국어 미지원 |
| 리전 `ap-northeast-2`, 모델 ID는 환경변수 `MODEL_ID` | 팀 규칙. 계정에서 사용 가능한 모델 확인 후 입력 |
| 얼굴 이미지 미저장 | 각도 값만 저장해 개인정보 최소화 |
| 면접 진행 규칙은 현지 함수, 저장·연결은 백엔드 | 백엔드는 꺼내고 → 부르고 → 저장만 하면 됨. 규칙 전달 과정의 오해와 버그를 줄이고, 현지는 DB 없이 샘플 데이터로 단독 테스트 가능 |
| 점수 계산은 세션 데이터를 받아 계산 | DB에 의존하지 않아 단독 테스트 가능 |
| 정면 보정 필수, 실패 시 태도 미측정 | 사전 테스트에서 정면을 봐도 시선 위아래가 약 -10° (노트북 카메라가 눈보다 아래). 기본값 0을 쓰면 정면도 아래로 판정됨 |
| 시선 기준을 좌우 ±15°, 위아래 ±8°로 분리 | 사전 테스트에서 눈만 내려 메모를 볼 때 위아래 차이가 약 10°라 ±15°로는 잡히지 않음 |
| Transcribe 결과는 팀 S3에 저장 후 읽기 | 기본 결과 주소는 인터넷 접근이 필요해 Lambda 네트워크 설정에 따라 실패할 수 있음 |

## 3. 사용 데이터

RAG·외부 공공데이터는 사용하지 않습니다. 사용자가 입력한 자소서와 면접 중 수집한 데이터로 동작합니다.

| 구분 | 데이터 | 출처 | 용도 |
| --- | --- | --- | --- |
| 입력 | 직무 (자유 입력) | 사용자 | 질문 생성 |
| 입력 | 자소서 텍스트 `resumeText` | 붙여넣기·샘플 / 팀 문서 기능 추출 결과 | 질문 생성, 꼬리질문 판단 |
| 입력 | 면접 유형 (인성/직무/혼합), 카메라 동의 | 사용자 | 질문 구성, 카메라 사용 여부 |
| 입력 (선택) | `profile` (목표 직무, 프로젝트 경험, 보유 기술, 주요 강점, 확인이 필요한 역량) | 팀 역량 분석 기능 | 질문·꼬리질문 소재 |
| 수집 | 답변 녹음 | 브라우저 | Transcribe 변환 (변환 후 삭제) |
| 수집 | 카메라 캡처 이미지 | 브라우저 | Rekognition 분석 (저장하지 않음) |
| 생성 | 답변 텍스트 + 단어별 시간 | Transcribe | 내용 평가, 발화 속도·침묵 측정 |
| 생성 | 시선·고개 각도, 유효 여부 | Rekognition | 태도 점수 |
| 생성 | 질문, 꼬리질문 판단, 내용 평가, 피드백 | 면접관 에이전트 | 면접 진행, 리포트 |
| 참고 | 공통 질문 예시 10개 | 직접 작성 | 질문 스타일 참고 (프롬프트 A) |
| 참고 | 경험·지식·상황 평가표 | 직접 작성 | 내용 평가 기준 (프롬프트 C-1) |
| 참고 | 점수 설정 파일 (`scoring_version` v1.0) | 직접 작성 | 전달력·태도·종합 점수 기준 |
| 시연 | 가상 자소서 1명분 (백엔드 개발) | 직접 작성 | 데모 |

## 4. 기능 상세

### 4.1 기능 목록

| ID | 기능 | 담당 | 설명 |
| --- | --- | --- | --- |
| F-01 | 면접 설정 | 프론트 + 백엔드(세션 저장) + 현지(`start_interview`) | 직무, 자소서, 면접 유형, 카메라 동의 입력 → 세션 생성 |
| F-02 | 질문 생성 | 현지 (AI) | 직무·자소서·유형으로 기본 질문 3개 + 유형(경험/지식/상황) 생성 |
| F-03 | 장비 점검·정면 보정 | 프론트 + 백엔드(저장) + 현지(`analyze_face`, `compute_baseline`) | 마이크 확인, 카메라 3초 보정 → 정면 기준값 저장 |
| F-04 | 음성 질문 | 현지 | Polly로 질문 음성 생성. 재생 실패 시 자막 + [답변 시작] |
| F-05 | 답변 녹음·제출 | 프론트 + 백엔드(업로드·중복 확인) | 최대 2분, 30초·10초 전 알림, 2분 시 자동 제출, 중복 제출 거절 |
| F-06 | 음성 변환·전달력 측정 | 현지 | Transcribe 변환 → 발화 속도, 분당 긴 침묵, 시간 관리 |
| F-07 | 꼬리질문 판단 | 현지 (AI) | 답변이 추상적이거나 자소서와 다르면 추가 질문 1개 |
| F-08 | 시선 분석 | 현지 | 답변 중 2초 간격 캡처 → 시선·고개 각도 → 정면 응시 비율 |
| F-09 | 점수 계산 | 현지 (코드) | `calculate_interview_scores(session, frames, config)`: 영역별·종합 점수, 등급, 미측정 사유 |
| F-10 | 리포트 생성 | 현지 (AI + 코드) | `generate_report`: 내용 평가(C-1) → 태도 측정 → 점수 계산 → 피드백(C-2) → 백엔드가 저장 |
| F-11 | 다음 행동 연결 | 프론트 | [자소서 보완하기] → 서류 첨삭, [부족한 역량 학습하기] → 학습 로드맵 |

### 4.2 고정 규칙

- 기본 질문 3개, 꼬리질문 문항당 최대 1개 (`process_answer`가 검사)
- 답변 최대 2분 (질문 음성 종료 후 시작, 재생 실패 시 [답변 시작] 클릭 시부터)
- 중간 종료·건너뛰기·다시 녹음 없음
- 무응답·변환 실패는 "평가 불가"로 기록하고 이유(`NO_ANSWER` / `TRANSCRIBE_FAILED`) 저장
- 카메라 미동의·실패 시 음성만으로 진행, 태도는 미측정

### 4.3 점수 요약

상세 기준은 기능 정리 페이지 6번을 따릅니다.

| 영역 | 계산 주체 | 방식 |
| --- | --- | --- |
| 내용 | AI (C-1) | 유형별 4개 항목 × 1~5점 → 합계 ÷ 20 × 100, 기본 + 꼬리 묶음 평가 |
| 전달력 | 코드 | 시간 관리 10 + 발화 속도 30 + 분당 긴 침묵 30 → 측정된 항목 기준 100점 환산 |
| 태도 | 코드 | 정면 응시 비율 80% 이상 100점, 40% 이하 0점. 시선 좌우 ±15°·위아래 ±8°, 고개 ±20°. 눈 감음은 확신도 80% 이상일 때만 제외. 유효 캡처 10장 미만 또는 정면 보정 없음이면 미측정 |
| 종합 | 코드 | 50/25/25 기본, 미측정 영역은 제외하고 비율 재조정 |
- 평가 가능한 답변 0개: 점수·등급 없이 안내
- 평가 가능한 기본 질문 1~2개: 점수 계산 + "평가 가능한 기본 질문 N/3개 기준" 표시

## 5. API 명세 (백엔드 참고용 제안)

백엔드 담당이 최종 결정합니다. 현지 함수는 API 형식과 무관하게 동작하므로, 프론트와 백엔드가 필드 이름만 맞추면 됩니다.

### 5.1 공통 규칙

| 항목 | 내용 |
| --- | --- |
| Base URL | `/api/v1/interview` |
| 형식 | JSON (녹음·이미지는 `multipart/form-data`) |
| 필드 이름 | 카멜 표기 |
| 인증 | Cognito JWT (결정 기록 D-07). 모든 요청에 `Authorization: Bearer {accessToken}`. 없거나 틀리면 401. userId는 토큰의 `sub`로 서버가 읽고, 요청 본문·쿼리의 userId는 쓰지 않음 (`docs/api.md`) |
| 긴 처리 | HTTP 202 + `sessionId` → `/status`로 확인 |
| 상태 값 | `status`: `PENDING` / `PROCESSING` / `COMPLETED` / `FAILED` |
| 세부 단계 | `stage`: `QUESTION_GENERATING` / `NEXT_QUESTION_READY` / `TRANSCRIBING` / `JUDGING` / `REPORT_GENERATING` / `REPORT_READY` |

**오류 형식** (팀 공통)

```json
{
  "error": {
    "code": "ANSWER_ALREADY_SUBMITTED",
    "message": "이미 제출된 답변이에요.",
    "requestId": "req-7f3a...",
    "retryable": false
  }
}
```

| 코드 | HTTP | 상황 | retryable |
| --- | --- | --- | --- |
| `INVALID_INPUT` | 400 | 필수 값 누락, 형식 오류 | false |
| `SESSION_NOT_FOUND` | 404 | 없는 세션 | false |
| `INVALID_STATE` | 409 | 지금 단계에서 받을 수 없는 요청 (예: 질문 준비 전 답변 제출) | false |
| `ANSWER_ALREADY_SUBMITTED` | 409 | 이미 제출된 `answerId` | false |
| `FILE_TOO_LARGE` | 413 | 녹음·이미지 용량 초과 | false |
| `AI_OUTPUT_INVALID` | 500 | AI 출력 형식·범위 검사 실패 (재시도 후에도 실패) | true |
| `AWS_SERVICE_ERROR` | 503 | Bedrock·Polly·Transcribe·Rekognition 호출 실패 | true |
| `INTERNAL_ERROR` | 500 | 기타 서버 오류 | true |

### 5.5 POST `/api/v1/interview/frame`

카메라 캡처 이미지 분석. Rekognition 결과 중 각도만 저장하고 이미지는 저장하지 않습니다.

**요청** (`multipart/form-data`)

| 필드 | 필수 | 설명 |
| --- | --- | --- |
| `sessionId` | O | 세션 ID |
| `type` | O | `CALIBRATION` (정면 보정) / `ANSWER` (답변 중) |
| `questionId`, `answerId` | `ANSWER`일 때 | 답변 구분 |
| `capturedAt` | O | 캡처 시각 (ISO 8601) |
| `image` | O | JPEG, 5MB 이하 |

**응답 200**

```json
{ "accepted": true, "valid": true }
```

- 답변 제출 이후 도착한 `ANSWER` 이미지는 `accepted: false` (점수에서 제외)
- 얼굴 없음·여러 명·가려짐·흐림·신뢰도 낮음 → `valid: false` (감점 아님). 눈 감음은 `eyesOpen`으로 넘기고 점수 계산 단계에서 판단

### 5.6 프론트 전달 규칙

| 항목 | 규칙 |
| --- | --- |
| 면접 시작 | `NEXT_QUESTION_READY` 그리고 마이크 사용 가능일 때 [면접 시작] 활성화 |
| 2분 타이머 | 질문 음성 종료 시 시작 (재생 실패 시 [답변 시작] 클릭 시). 30초·10초 전 알림, 2분 시 `timeLimitReached: true`로 자동 제출 |
| 캡처 | 보정 0.5초 간격 3초, 답변 중 2초 간격 |
| 답변 완료 | 버튼 비활성화 → 캡처 중단 → 전송 중 이미지 최대 3초 대기 → `/answer` 제출 |
| 상태 문구 | `TRANSCRIBING` 음성 변환 중 / `JUDGING` 다음 질문 준비 중 / `REPORT_GENERATING` 리포트 생성 중 |
| 오류 | `retryable: true`면 다시 시도 버튼, false면 안내 문구 |

## 6. DB 모델 (`docs/db-schema.md` §2.4 기준, 결정 기록 D-13·D-20)

현지 함수는 세션 데이터(`session`)를 받고 돌려주므로, 백엔드는 이를 그대로 저장하면 됩니다. 저장 구조는 팀 공통 DB 스키마를 따릅니다. 이 절과 `docs/db-schema.md` §2.4가 다르면 `db-schema.md`를 따릅니다.

테이블 `team07-career-mentor`(PK `USER#{userId}`, userId는 인증 정보에서만 읽음)에 면접 항목을 SK로 구분합니다. 세션 데이터는 함수가 돌려준 그대로 한 항목에 저장하고, 2초마다 들어오는 캡처는 동시 저장 충돌을 피하기 위해 별도 항목으로 저장합니다.

| SK | 내용 |
| --- | --- |
| `INTERVIEW#{ivId}` | 현지 함수가 돌려준 `session` 그대로 + 백엔드 관리 값: `status`, `stage`, `expectedAnswerId`, `submittedAnswerIds[]`, `transcribeJobs{answerId: {jobName, audioKey, timeLimitReached}}`, `nextQuestion`, `lastAnswer`, `jobRole`(= session.job), `workspaceId` |
| `INTERVIEW#{ivId}#FRAME#{answerId}#{capturedAt}` | `type`(CALIBRATION/ANSWER), `accepted`, `valid`, `gaze`, `head`. **이미지는 저장하지 않음**. 보정 캡처는 answerId 자리에 `CALIBRATION` |
| `INTERVIEW#{ivId}#REPORT` | `report`. 다시 열면 이 값을 그대로 반환 |
- `ivId` = 이 명세의 `sessionId` (UUID, 백엔드 생성. 인증 수단이 아님)
- `answerId`: 현지 함수가 질문과 함께 발급, 백엔드가 조건부 쓰기로 중복 제출 방지 (409). 제출 뒤 도착한 캡처는 `accepted=false`
- `compute_baseline`은 리포트 직전 `CALIBRATION` 캡처로 호출하고 결과를 `session.baseline`에 저장
- `start_interview` 입력: `resumeText` 또는 `documentId`(→ `DOC_LATEST#`의 `extractedTextKey`). `profile`은 `PROFILE#LATEST` 최신 버전의 `projects`, `skills`, `needsConfirmation`
- 보관: 녹음과 Transcribe 결과 파일은 변환이 끝나면 바로 삭제 (`uploads/` 7일 자동 삭제는 안전장치). 얼굴 이미지는 저장하지 않음. 회원 탈퇴 때 `USER#{userId}` 아래 항목과 `uploads/interview/{ivId}/`를 함께 삭제 (`db-schema.md` §2.6)
- 이번 변경으로 `db-schema.md` §2.4에 추가될 필드 (반영은 백엔드 담당): `transcribeJobs`의 `transcriptKey`, FRAME의 `eyesOpen`, `baseline`이 `None`일 때의 동작

## 7. 품질 검증

- **함수 단위 테스트 (현지)**: `interview/samples/`의 가짜 세션 데이터로 DB 없이 테스트
- **연결 테스트 (백엔드·프론트와 함께)**: 아래 시나리오

| 시나리오 | 기대 결과 |
| --- | --- |
| 정상 진행 (질문 3개 + 꼬리질문) | 리포트 완료, 3개 영역 점수 표시 |
| 카메라 미동의 | 음성만 진행, 태도 미측정, 내용 70% + 전달력 30% |
| 무응답 (말하지 않고 제출) | 평가 불가(답변 없음), 다음 기본 질문으로 진행 |
| Transcribe 실패 | 평가 불가(변환 실패), 면접 계속 진행 |
| 2분 초과 | 자동 제출, 시간 관리 8점 |
| [답변 완료] 두 번 클릭 | 두 번째 요청 409 |
| 15초 미만 답변 | 발화 속도·침묵 미측정 |
| 숫자·영어가 많은 답변 | 발화 속도 미측정 |
| 꼬리질문 2개 이상 요청 (AI 출력) | `process_answer`가 1개로 제한 |
| AI 출력 형식 오류 | 재시도 후 실패 시 `AI_OUTPUT_INVALID` |
| 평가 가능한 답변 0개 | 점수·등급 없이 안내 |
| 눈만 아래로 내려 메모 보기 | 정면 아님으로 판정 (분석 제외 아님) |
| 정면 보정 실패 (유효 3장 미만) | 태도 미측정, 내용 70% + 전달력 30% |
| 리포트 다시 열기 | 저장된 같은 결과 반환 |
- 질문 품질: 시연 직무(백엔드 개발) 가상 자소서로 질문이 자소서 내용을 반영하는지 확인
- 기준 확인: 팀원 3~4명 모의 답변 녹음으로 발화 속도·침묵 기준 점검

## 8. 모니터링

- CloudWatch 로그: `requestId`, `sessionId`, `stage`, 처리 시간, 오류 코드
- 로그에 **자소서·답변 원문, 얼굴 이미지, 자격 증명을 남기지 않음**
- 확인할 지표: Transcribe 변환 시간, AI 응답 시간, 단계별 실패 건수
- 로그 그룹·알림 설정은 백엔드 담당 (팀 공통 설정)
- 현지 함수는 원문 없이 단계, 처리 시간, 오류 코드만 로그

- 백업: 화면에 노출하지 않는 텍스트 면접 모드, 백업 시연 영상
